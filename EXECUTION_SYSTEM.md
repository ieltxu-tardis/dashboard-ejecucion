# EXECUTION_SYSTEM.md

## Objetivo
No perder contexto, convertir ideas en entregables, y sostener progreso aunque haya contexto cambiante.

## Regla principal
**Nada importante vive en la cabeza.** Todo entra por Inbox y termina en un estado visible.

## Flujo (muy corto)
1. **Capture** → anotar en `NEXT_ACTIONS.md` (Inbox)
2. **Clarify** → definir resultado + primer paso (<=15 min)
3. **Commit** → elegir Top 3 del día
4. **Execute** → bloques de foco de 45-90 min
5. **Close** → actualizar estado + siguiente acción

## Estados permitidos
- `INBOX`
- `NEXT`
- `BLOCKED`
- `WAITING`
- `DONE`

## WIP limit
- Máximo **3 tareas NEXT** activas a la vez.

## Definición de Done
Una tarea está DONE solo si dejó evidencia:
- commit / doc / mensaje enviado / issue cerrada.

## Ritual diario (10-15 min)
- AM: elegir Top 3
- PM: cerrar día (qué se completó, qué quedó bloqueado, siguiente paso)

## Anti-context-switch protocol
Antes de cambiar de tarea/proyecto, escribir:
- qué estaba haciendo
- próximo paso exacto
- link/archivo de continuidad

Formato rápido:
`RESUME: <proyecto> | next: <paso> | ref: <archivo/link>`

## Cadencia semanal (30 min)
- Revisar DONE
- Eliminar/archivar ruido
- Re-priorizar backlog por impacto
- Ajustar 1 regla del sistema (máximo una por semana)
